# 구솔라 추가 지시: 인바운드 3389 방화벽 확정 재시도 + 텔레그램 수신 가능 여부 확정

## 목적
- 구PC 인바운드 3389 Allow 규칙 존재 여부를 가능한 범위에서 다시 확정한다
- 구솔라 쪽 텔레그램 수신 가능 여부를 가능한 범위에서 확정한다

## 배경
- check-rdp-firewall-3389-100.98.73.90: 완료(부분), 인바운드 3389 Allow 미확정
- 구솔라_0순위_후속_방화벽3389_확정_텔레그램확인: 완료(부분), 인바운드 3389 Allow 미확정, 텔레그램 수신 여부 확정 불가
- 구PC에서 3389 LISTEN, TermService RUNNING, RDP-Tcp 포트 3389는 이미 확인됨
- 인바운드 3389 Allow 규칙은 관리자 권한 부족으로 아직 확정하지 못함

## 현재 확인된 것
- 구PC: 100.98.73.90 active, 직접 경로 172.30.1.5:41641
- TermService RUNNING
- RDP-Tcp Listening on 0.0.0.0:3389
- NLA=0, SecurityLayer=0
- 방화벽 프로파일 활성화 상태
- 방화벽 인바운드 3389 Allow 규칙은 미확정

## ACTION

### 1) 인바운드 3389 방화벽 허용 여부 재확인
가능하면 관리자 권한 PowerShell에서 아래를 확인한다.

- 인바운드 3389 Allow 규칙이 있는지
- TCP 3389 인바운드 트래픽을 허용하는 NetFirewallRule이 존재하는지
- 공용/사설/도메인 프로파일 기준으로 3389 인바운드는 어떤 상태인지
- 가능하다면 netstat/Get-NetTCPConnection으로 0.0.0.0:3389 LISTEN 재확인
- 불가능하면 왜 불가능한지, 어떤 조건에서 안 되는지 결과로 남긴다

성공 기준:
- 인바운드 3389 Allow 규칙 존재 여부를 알기 쉽게 보고
- 존재하지 않는다고 판단할 경우에도 그 근거를 남긴다
- 관리자 권한 부족으로 확인이 안 되면 그 사실을 명시한다

### 2) 텔레그램 수신 가능 여부 확정
가능하면 아래를 확인한다.

- 구PC에서 텔레그램 앱이 실행 가능한 상태인지
- 봇 알림이나 채널 알림을 받을 수 있는 구성인지
- 받은 알림을 구솔라가 확인할 수 있는지
- 불가능하면 앱 실행 상태, 계정 상태, 봇/채팅 미연결 등 사유를 남긴다
- 민감정보(토큰, 채팅 ID, 봇 토큰 등)는 남기지 않는다

성공 기준:
- 구솔라가 텔레그램 수신 가능 여부를 알기 쉽게 보고
- 가능하면 어떤 형태로 수신이 되는지 정리
- 불가능하면 왜 불가능한지 정리

### 3) INDEX 및 상태 관리
- 결과를 push할 때 INDEX 반영이 필요하면 함께 반영한다
- 구솔라가 완료하면 incoming에서 문서를 지우지 말고 결과 파일로 상태를 남긴다
- 중복처럼 보이는 TASK는 임의로 삭제하지 말고, 상태만 남기거나 신솔라에게 알린다

## VERIFICATION

신솔라는 아래를 직접 확인한다.

- 구솔라가 push한 결과 파일이 실제로 tasks/completed/와 reports/에 있는지
- 인바운드 3389 Allow 규칙 확정 시도 결과가 남았는지
- 텔레그램 수신 가능 여부 판단이 남았는지

## EXPECTED_OUTPUT

- tasks/completed/구솔라_0순위_후속_방화벽3389_확정_텔레그램확인_result.md 또는 후속 결과 파일에 인바운드 3389 Allow 판단 기록
- reports/구솔라_0순위_후속_방화벽3389_확정_텔레그램확인.md 또는 후속 보고서에 요약
- 텔레그램 수신 가능 여부 판단 기록

## 주의사항

- 말만 하고 결과로 남기지 않으면 완료로 보지 않는다
- 관리자 권한 없어서 확인이 안 되면 그 사실을 정확히 남긴다
- 텔레그램 수신 가능 여부는 "모른다"로 끝내지 말고 가능한 범위에서 판단한 결과를 남긴다
- INDEX 상태를 실제와 다르게 두지 않는다
