# 구솔라 진입 워크플로 (복귀 표준)

이 문서는 구솔라가 세션이 끊겼다가 다시 들어오는 경우, 또는 새로 솔라 생태계에 합류해 들어왔을 때 먼저 따라야 하는 표준 절차다.

목표:
- 구솔라가 무엇을 먼저 해야 하는지 망설이지 않게 한다
- 파워쉘만 다시 열어서 끝나는 게 아니라, 저장소 최신화부터 하게 한다
- 현재 TASK를 보고 실제 업무를 이어가게 한다
- 작업 상태를 말로만 남기지 않고 저장소에 남기게 한다

사용 대상:
- 구솔라
- 솔라 생태계에 처음 들어와 구PC 측 작업을 맡는 사람

---

## 1. 첫 진입

파워쉘 또는 터미널을 연다.

이미 저장소를 한 번이라도 복제한 적이 있으면 그 디렉토리로 간다.

```bash
cd <구PC의 hermes-node-bridge 경로>
```

처음이면 clone한다.

```bash
git clone https://github.com/hansunghee7/hermes-node-bridge.git
cd hermes-node-bridge
```

## 2. 최신화

반드시 pull한다.

```bash
git pull
```

최신화하지 않으면 현재 TASK를 놓친다.

## 3. 현재 TASK 확인

들어오자마자 아래를 본다.

- INDEX.md
- tasks/incoming/ 폴더 전체

가장 위에 있는 미처리 TASK부터 본다.

## 4. 복귀 직후 우선순위

복귀 직후에는 아래 순서로 본다.

- GU_SOLAR_RECOVERY_BRIEF.md
- GU_SOLAR_CHECKLIST.md
- INDEX.md
- tasks/incoming/의 최상단 TASK

현재 최우선 TASK는 구PC가 실제로 이어서 처리해야 하는 TASK다. 읽었으면 바로 실행한다.

## 5. 실행 전 확인

작업 시작 전에 다음을 확인한다.

- 저장소가 최신인지
- 이미 완료된 TASK를 다시 처리하려는 건 아닌지
- 현재 구PC Tailscale 연결 상태를 직접 확인할 수 있는지
- 관리자 권한이 필요한 작업인지
- 방화벽, 서비스, 포트 등 현재 상태를 확인 없이 추정하지 않는지

## 6. 실행

TASK 문서대로 실행한다.

- 추정 대신 직접 확인한다
- 현재 Tailscale IP, 현재 서비스 상태, 현재 포트 상태는 직접 본다
- 과거 IP, 과거 세션, 과거 보고서를 현재 사실처럼 쓰지 않는다

## 7. 결과 기록

결과를 말로만 남기지 않는다.

- 완료했으면 tasks/completed/에 결과 문서를 남긴다
- 실패했으면 tasks/failed/에 결과 문서를 남긴다
- 보고서는 reports/에 남긴다
- TASK_ID를 반드시 남긴다

기록할 때는 다음이 들어가게 한다.

- TASK_ID
- 실행자
- 실행 시각
- 실행 대상
- 실제 확인한 내용
- 실패/미확인 항목
- 다음 단계

## 8. push

결과를 저장소에 올린다.

```bash
git add tasks/completed/ tasks/failed/ reports/
git commit -m "구솔라: <TASK_ID> 완료"
git push
```

## 9. 진입 후 종료/재연결 대비

- 중간중간 상태가 바뀌면 가능한 범위에서 문서로 남긴다
- 세션이 끊길 수 있으면, 끊기기 전에 현재 진행 상태와 다음 액션을 남긴다
- 다시 들어왔을 때 이전 맥락을 추측하지 않아도 되게 한다

## 10. 주의사항

- 파워쉘을 다시 여는 것만으로 업무가 이어지는 게 아니다
- 헤르메스만 실행한다고 현재 TASK를 아는 게 아니다
- 저장소 최신화 없이 과거 TASK를 처리하지 않는다
- 현재 증거가 없으면 추측하지 않는다
- 작업 범위를 임의로 늘리지 않는다
- 핵심 목표를 문서로 대체하지 않는다

---

이 문서는 솔라 바이블을 실제로 진입 동작으로 옮긴 표준 절차다.

구솔라는 이 문서를 보고 들어와서, 최신화 → TASK 확인 → 실행 → 결과 기록 → push 순서로 움직인다.

신솔라는 이 절차가 실제로 지켜졌는지 저장소 문서로 확인한다.
